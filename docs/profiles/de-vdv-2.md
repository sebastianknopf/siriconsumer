# German VDV 453/454 Profile, Version 2

Profile ID: `de-vdv`  
Version: `2`

This profile targets VDV 453 2.6.1 and VDV 454 2.2.1 using the common V2017e XML schema generation. It uses fetched delivery only.

## Service Mapping

The public API always uses SIRI service names. The profile maps them internally:

| SIRI Service | VDV Service | VDV Subscription Element | Required Parameter |
| --- | --- | --- | --- |
| `CT` | `REF-ANS` | `AboASBRef` | `asbId` |
| `CM` | `ANS` | `AboASB` | `asbId` |
| `ST` | `REF-DFI` | `AboAZBRef` | `azbId` |
| `SM` | `DFI` | `AboAZB` | `azbId` |
| `VM` | `VIS` | `AboVIS` | `visId` |
| `PT` | `REF-AUS` | `AboAUSRef` | none |
| `ET` | `AUS` | `AboAUS` | none |

`asbId`, `azbId`, and `visId` are read from the generic `parameters` object and are required only for the services shown above.

## Identifiers

`requestor_ref` becomes the VDV `Sender` of requests generated by the consumer. `producer_ref` contains the producer control-centre identifier agreed with the remote system and is required for callback routing. `subscription_ref` becomes the VDV `AboID` while remaining the globally unique local subscription identity.

## Consumer Callback URL

The VDV-specific part of the generic profile URL follows:

```text
/consumer/profile/de-vdv/2/{producer_ref}/{VDV-service}/{action}.xml
```

Examples:

```text
POST /consumer/profile/de-vdv/2/PRODUCER/AUS/datenbereit.xml
POST /consumer/profile/de-vdv/2/PRODUCER/AUS/clientstatus.xml
POST /consumer/profile/de-vdv/2/PRODUCER/VIS/datenbereit.xml
```

The VDV service in the callback path is mapped back to the SIRI service code stored in the subscription. Multiple subscriptions may share the same `producer_ref` and service; a matching data-ready callback schedules each matching subscription.

## Publisher URLs

`provider_url` remains the configured publisher-side base URL. The profile appends the action-specific VDV endpoint, including `aboverwalten.xml`, `status.xml`, and `datenabrufen.xml`.

## Parameters

Example for a VIS subscription:

```json
"parameters": {
  "visId": "VIS-AREA-12345"
}
```

For ANS/REF-ANS use `asbId`; for DFI/REF-DFI use `azbId`. AUS and REF-AUS currently require no profile-specific parameter.
